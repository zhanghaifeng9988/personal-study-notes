移动分区表的语句

1、移动非组合分区表到新的表空间
ALTER TABLE [table_name] MOVE PARTITION [partition_name] TABLESPACE [tablespace_name]  nologging parallel 8 compress;
2、移动组合分区表
1）先移动子分区到另一个表空间
alter table [table_name] move SUBPARTITION [subpartition_name] tablespace [tablespace_name] nologging parallel 8 compress;
2）再修改父分区的属性为另一个表空间
ALTER TABLE [table_name] MODIFY DEFAULT ATTRIBUTES FOR PARTITION [partition_name] TABLESPACE [tablespace_name];





和分区相关的索引概念有很多，有本地索引和全局索引，

本地索引：本地索引一定是分区索引，分区键等同于表的分区键，分区数等同于表的分区数，
一句话，本地索引的分区机制和表的分区机制一样。
对于本地索引，其索引分区的维护自动进行，就是说你add/drop/split/truncate表的分区时，
本地索引会自动维护其索引分区。

前缀索引：
1）当本地索引列只有一列，而该列正是表的分区列时。
2）如果本地索引列是组合多列，那么第一列必须是表分区列。
非前缀索引：与前缀索引相反，索引列中不包含分区列


本地索引:1.本地前缀分区索引    2.本地非前缀分区索引。

前缀和非前缀索引都可以支持索引分区消除，前提是查询的条件中包含索引分区键。
本地索引只支持分区内的唯一性，无法支持表上的唯一性，
因此如果要用本地索引去给表做唯一性约束，
则约束中必须要包括分区键列。

本地分区索引是对单个分区的，每个分区索引只指向一个表分区，
全局索引则不然，一个分区索引能指向n个表分区，同时，一个表分区，也可能指向n个索引分区，
对分区表中的某个分区做truncate或者move，shrink等，可能会影响到n个全局索引分区，
正因为这点，本地分区索引具有更高的可用性。

位图索引只能为本地分区索引。


全局索引：
全局索引即可以分区，也可以不分区。即可以建range分区，也可以建hash分区，即可建于分区表，
又可创建于非分区表上，就是说，全局索引是完全独立的，因此它也需要我们更多的维护操作。

1.分区键和分区数和表的分区键和分区数可能都不相同，表和全局索引的分区机制不一样。
2.全局索引可以分区，也可以是不分区索引，全局索引必须是前缀索引，
即全局索引的索引列必须是以索引分区键作为其前几列。
3.全局分区索引只按范围或者散列hash分区，hash分区是10g以后才支持。
4.全局索引多应用于oltp系统中
5.全局分区索引的索引条目可能指向若干个分区，因此，
对于全局分区索引，即使只截断一个分区中的数据，都需要rebuild若干个分区甚至是整个索引。
可以查询dba_ind_partitions，或者user_ind_partitions，找到partition_name，
然后对每个分区重建
select index_name,partition_name from user_ind_partitions where index_name='INDEX_NAME';
alter index 全局索引名 rebuild partition 分区名 online nologging;

6.oracle9i以后对分区表做move或者truncate的时候，可以用update global indexes语句
来同步更新全局分区索引，用消耗一定资源来换取高度的可用性。
7.全局分区索引只能是B树索引；
8.Oracle默认不会自动维护全局分区索引；


全局索引:1.全局非分区索引      2.全局分区索引

关于分区索引的几个视图：
dba_ind_partitions 描述了每个分区索引的分区情况，以及统计信息
dba_part_indexes 分区索引的概要统计信息，可以得知每个表上有哪些分区索引，分区索引的类型(local/global)
dba_indexes minus dba_part_indexes （minus操作）可以得到每个表上有哪些非分区索引

从以上索引的结构不难看出，全局索引的维护工作更加复杂，本地索引具有更高的可用性。
从可维护的角度看：我们更倾向于选择本地索引。

创建本地索引时，索引分区和表分区数量必须相同
如果创建本地索引时指定分区，需要和表分区数量相同。
