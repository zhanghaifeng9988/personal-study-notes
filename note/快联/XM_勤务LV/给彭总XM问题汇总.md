
***XM_QW的这个单子，我看到的一些情况：***

# 一、非软件相关情况
 1、应用软件系统的要求和3月份你给我的方案（你告诉我说：这个方案是XM_QW的方案，清华TF做的设计内容）中的描述是吻合的；
 2、单Z保障卡和读卡器的内容，我对比了去年黄金塘车场的清单内容（清单是设计院给的）和徐州车场的项目，这个清单中的内容与这两个都不相同。
 3、这个清单的制作格式，跟GX是一个风格。
 4、AI维修助手，这个采购内容，
(1. 需要落实清楚需求、技术实现软硬件选型、工作内容，交付物定义。否则可能会造成范围蔓延，交付物不清晰，工作责任不清晰、数据安全等问题。
(2.配套的训练服务器，即清单中的“服务器-2”这个设备是1台，按照我的个人经验，这台服务器主要为"AI维修助手"这个业务软件功能，进行LLM的多模态模型训练的设备，这里面存在的问题是：
**A、 训练用的是开源模型还是闭源模型，是国外还是国内的？是否符合用户的安全要求?** 
**B、 训练完成的模型是直接做API接口供业务软件远程调用呢？还是将模型打包后导出，然后部署到业务系统的生产环境中，作为插件本地调用？**
**C、  这台服务器应该是在SM网中运行才行，这一点需要确认**
 5、需要论证业务服务器和双机热备软件配置的合理性：4台高性能物理机，如果做虚拟化话，单台服务器应该可以虚拟5台左右高性能虚拟机，4台服务器就是20台虚拟机，应该足可以满足生产环境中，业务软件服务、中间件和数据库的HA,不知道单独配置双机热备软件2套的目的是什么？
 6、数据库的配置，买单实例,可以做主库备库双机，实现读写分离就可以。2套的这个定义，存在技术解决方案，选型不明确的问题。

 8、除了上述第7项描述的内容，硬件部分的其他设备，都是找合适的供应商采购即可。

# 二、软件的1个问题
根据我们现在潮州维修项目的经验和已知情况，用户的仓库管理系统如果联网的话，是连接**君粽网**的，如果这个项目的软件是在非**君粽网**的环境里面的，那么这一项应该是无法通过API接口实现数据和功能的互联互通的。

建议：
# 1. **智慧维修助手--相关建议**
1）建议用deepseek的开源模型进行AI知识库搭建和模型训练；
2）要提前测算一下训练的数据量、数据类型、数据质量，根据数据量和数据类型，选择合适的模型，进而匹配硬件配置，硬件配置要尽量留有冗余，算力要多配置；
3）正式大规模训练前，要先进行小规模实验，验证模型选型的合理性，适当的调整模型的选型。
# 2. **与装备器材供应保障（仓库）系统接口--相关建议**
1）该系统是用户单位已经在运行的业务系统，且该系统只能在JZW上运行，属于SM场景的业务。如果建立接口，则需要能够实现“智慧工间应用软件系统”与“装备器材供应保障（仓库）系统”的互联互通。那么，“智慧工间应用软件系统”将需要在JZW上运行，或者用户“智慧工间应用软件系统”生产环境的网络与JZW可以互联互通。
# 3. **综合态势展现--相关建议**
1）综合态势展现的要求包含：ZB动用使用、分队携装、维护保养等数据信息，该类信息属于ZB动用管理的业务范围产生的数据，非维修业务产生数据。
2）用户是否已有ZB动用管理系统？如果有，需要增加数据互联互通的工作，如果没有需要增加ZB动用管理系统的建设内容。
# 4. **高可用--建议**
1）本次项目配置了双机热备软件进行配置，不建议使用此方式，因为双机热备软件存在单点故障问题；
2）建议解决办法：
本次项目配置的4台高性能物理机情况如下：
- cpu：2*4=8颗；8*10核=80核；单颗主频2.2GHz  ；
- 内存：128*4=512G；
- 存储1：480G SSD*4=1920G~=2T；
- 存储2：16T w转SAS盘 *3*4=128T；
（1）如果做虚拟化，单台服务器可以虚拟5台左右高性能虚拟机，4台服务器就是20台虚拟机，可以满足生产环境需求；同时将所有存储都做成VSAN模式,从而利用计算资源和存储资源的虚拟化，实现业务软件、中间件和数据库的HA。
（2）将热备软件的预算更换成**存储设备**，用于日常生产数据的全量备份和差异备份。
# 5、**数据库--建议**
1、目前用户所管辖装备数量和业务并发预期并不是很大，数据库完全可以部署在虚拟机上；
2、数据库的HA配置建议采用**主从**的方式，主库和从库都部署在不同的物理机上，实现读写分离；当主库出现故障时，可以切换到从库，保证业务的连续性；
# 6、**生产环境监控--建议**
本次项目没有配置生产环境的监控系统，建议在生产环境中配置监控系统，包括：
1）监控指标：
2）虚拟机监控：监控虚拟机的CPU使用率、内存使用率、磁盘I/O、网络流量等指标。
3）数据库监控：监控数据库的连接数、查询性能、缓存命中率、表空间使用情况等。
4）存储监控：监控 vSAN 存储的使用情况、性能指标（如IOPS、延迟）。
5）告警机制：配置告警规则，当监控指标超过预设阈值时，通过邮件、短信等方式通知运维人员。
6）日志分析：使用日志分析工具（如 ELK 堆栈）收集和分析系统日志，及时发现潜在问题。
