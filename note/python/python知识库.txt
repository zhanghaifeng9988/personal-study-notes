序列化之后，就可以把序列化后的内容写入磁盘，或者通过网络传输到别的机器上。
>>> import pickle
>>> d = dict(name='Bob', age=20, score=88)
>>> pickle.dumps(d)
b'\x80\x04\x95$\x00\x00\x00\x00\x00\x00\x00}\x94(\x8c
\x04name\x94\x8c\x03Bob\x94\x8c\x03age\x94K\x14\x8c\x05score\x94KXu.'
>>> f = open('dump.txt', 'wb')
>>> pickle.dump(d, f)
>>> f.close()

           反序列化
从序列化的对象重新读到内存里称之为反序列化，即unpickling。
>>> f = open('dump.txt', 'rb')
>>> d = pickle.load(f)
>>> f.close()
>>> d
{'age': 20, 'score': 88, 'name': 'Bob'}
Pickle的问题和所有其他编程语言特有的序列化问题一样，就是它只能用于Python，
并且可能不同版本的Python彼此都不兼容，因此，只能用Pickle保存那些不重要的数据，不能成功地反序列化也没关系。

#对实例的序列化和反序列化

  #序列化
class Student(object):
     def __init__(self,name,age,score):
          self.name=name
          self.age=age
          self.score=score

s=Student('zhf',40,88)

def student2dict(s):
     return{
          'name':s.name,
          'age':s.age,
          'score':s.score
     }

print(json.dumps(s,default=student2dict))


  #反序列化
  
def dict2student(d):
    return Student(d['name'], d['age'], d['score'])
	
print(json.loads(json_str, object_hook=dict2student))



###进程和线程

举例：word是进程，打印、修改等等功能就是线程


总结一下就是，多任务的实现有3种方式：

多进程模式：多个进程，每个进程包含一个线程
多线程模式：1个进程包含多个线程
多进程+多线程模式：多个进程，每个进程包含多个线程


在多线程环境下，每个线程都有自己的数据。一个线程使用自己的局部变量比使用全局变量好，
因为局部变量只有线程自己能看见，不会影响其他线程，而全局变量的修改必须加锁。


是否采用多任务的第二个考虑是任务的类型。我们可以把任务分为计算密集型和IO密集型。
  要最高效地利用CPU，计算密集型任务同时进行的数量应当等于CPU的核心数。
  
IO密集型任务执行期间，99%的时间都花在IO上，花在CPU上的时间很少，因此，
用运行速度极快的C语言替换用Python这样运行速度极低的脚本语言，
完全无法提升运行效率。对于IO密集型任务，
最合适的语言就是开发效率最高（代码量最少）的语言，脚本语言是首选，C语言最差。


如果充分利用操作系统提供的异步IO支持，就可以用单进程单线程模型来执行多任务，
这种全新的模型称为事件驱动模型

                             python虚拟环境
							 
Python的虚拟环境是一个隔离的Python运行环境，它允许开发者为每个项目安装特定的库和版本，
避免不同项目之间的库版本冲突。虚拟环境与系统全局Python环境独立，可以避免对全局环境的污染。
通过使用虚拟环境，开发者可以为每个项目分别部署所需的第三方包，并确保这些包之间的兼容性。
创建和管理虚拟环境的模块是venv，它是Python 3.3及更高版本中内置的。
要创建虚拟环境，只需在命令行中运行python -m venv <虚拟环境名称>即可。

我的环境应该是anaconda，在win10环境
操作使用的是git的bash，命令如下：
