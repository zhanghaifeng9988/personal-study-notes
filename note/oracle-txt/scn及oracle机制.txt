
--DBWR的4个触发条件
①ckpt发生
②database buffer cache 脏块太多时(阈值)
③db_buffer自由空间不够时
④表空间read only/offline/backup模式等
 

--ckpt检查点触发的条件：
1、正常关闭数据库 shutdown immediate;
2、手动检查点切换 alter system checkpoint;
3、手动日志切换   alter system switch logfile;
4、数据库热备模式 alter database begin backup;

--LGWR的4个触发条件
1、commit;
2、3秒；
3、redo log buffer 三分之一满；
4、online redo switch；
先于dbwr写（先记后写，必须在dbwr写脏块之前写入日志，保证未提交数据都能回滚）

--SCN
SCN是一个单向递增的数字编号，控制文件、数据文件、在线Redo日志、归档日志和备份集合中，
都包括这个数字编号。在内部文件中，SCN是通过Base和Wrap两个部分进行保存。Base是SCN编号的基础位，
是通过32位二进制位进行保存。一旦超过这32位长度，系统会自动在Wrap进位。也就是说，Wrap表示的超过4G个数的进位次数。

--数据文件的RESETLOGS_CHANGE#表示数据库以resetlogs方式打开时的SCN，也可以通过v$datafile_header查询
oracle工作的基本原理，归档情况下：大家一定要同步，谁也不能滞后或者超前，也就是SCN号
为什么要resetlog，因为有一些地方不一致了，必须得需要着一个基准点，让大家以这个为起点，一起继续超前走。


select file#,resetlogs_change# from v$datafile_header;

alter database open noresetlogs与resetlog的区别：
resetlogs，由于不完全恢复导致日志不连续而不能使用恢复点之后的日志进行重做，所以使用resetlogs进行打开数据库。
noresetlogs，由于控制文件的版本是从备份中而来或是手工重建的，并且所有日志是连续的，可以用于重做，
所以使用noresetlogs打开数据库，意为使用log进行重做。

--current_scn 记录当前数据库dml的scn号，它是不断向前的，当ckpt被触发以后，
CHECKPOINT_CHANGE#的值瞬时大于current_scn

举例如下：
SYS@ orcl>select current_scn from v$database;

CURRENT_SCN
-----------
    9598713

SYS@ orcl>select current_scn from v$database;

CURRENT_SCN
-----------
    9598718

SYS@ orcl>select current_scn from v$database;

CURRENT_SCN
-----------
    9598721


alter system checkpoint;

SYS@ orcl>alter system checkpoint;

系统已更改。

SYS@ orcl>select CHECKPOINT_CHANGE# from v$database;

CHECKPOINT_CHANGE#
------------------
           9599375

SYS@ orcl>select current_scn from v$database;

CURRENT_SCN
-----------
    9599468
